# Native player (first integration)
C++17, Qt 6 Widgets and Multimedia. No Adobe runtime, Flash VM, or original projector at execution time. The original artwork is currently baked offline into 106 source-derived frame PNGs; the C++ timeline selects these frames. Native host reads original media through Qt, dispatches native playback and gallery events, reads the exact XML, and uses original hit-state bounds. The 5 embedded SWF MP3s are extracted without transcoding. Background playback state exists but the independent sprite compositing is not yet connected to the renderer; native controls are interim drawn chrome, not visually matched artwork. Sound envelope/loop behavior and hover artwork remain provisional. Native stage presentation uses letterboxing; original display scaling still needs comparison.
Build with Qt6 development packages: cmake -S . -B build -DPRESSKIT_BUILD_PLAYER=ON; cmake --build build. Prepare the verified original folder with tools/fetch_payload.py and use tools/prepare_player_assets.py with the reference-render workflow's original-frame-reference artifact. Run presskit_player <prepared directory>. The CI smoke test opens original MP4 intro and trailer, exercises original frame artwork, XML and gallery via native host. Qt backend is a chosen replacement, not a decompilation of Adobe libraries.
