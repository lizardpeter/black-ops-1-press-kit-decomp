# Native timeline orchestration

The root movie is 1280×720 (25600×14400 twips), 24 fps, 105 frames. Launcher nominal SWF bounds are 500×300, but its script centers a 1280×720 shell (see launcher source). Root frame 1 stops for intro, listener.complete at 485976 plays. Frame 75 stops for welcome, 81 stops for wallpapers (85 also stops), 91 stops for trailers, 95 stops for video, 101 stops for screenshots, 105 stops for gallery. Labels are 69 Welcome, 76 Wallpaper, 86 Videos, 96 Screens. The 75→76/86/96 jumps and forward playback are reconstructed from menu actions. The 91→95 and 101→105 transitions play, stop at destination, and hide nav and cursor. Close/completion installs stopRoll2 (prevFrame) on control, which is placed at 92/102 and removed at 91/101 respectively; 94/104 restores nav and close. The host timeline model treats this as backward stepping on ticks. Exact Flash callback scheduling and display lifecycle remain to be compared against an original-runtime capture.

Frame 91 starts music with original args 0,999999; the abstraction emits start_music, not sound samples. Selecting a visible trailer emits stop_music. At frame 95 playback depends on vid; only 1,2,4,5,6 have a visible instance. Frame 105 requests screenshot XML. Host events are modeled as effects, not yet bound to a window or video decoder.

Placement origins verified from SWF PlaceObject2 tags, not guessed from asset size. The three menu content sprites (136,157,220) all have root origin (526.85,43). Screens is a 5×4 grid (107,95 steps); wallpaper is four columns with two rows; trailers occupy five positions, no third control. Hit regions and graphics must be reconstructed from button state records and shape bounds. Coordinates are nominal local-stage pixels, not window coordinates. The runtime limits navigation to settled menus until event order is verified.
